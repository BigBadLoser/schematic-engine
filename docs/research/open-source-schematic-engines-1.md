# Open-source schematic generators: SKiDL, circuit-synth, tscircuit

Method: web reading of raw source via fetch (no clones). Statements come from summaries of the files named; quality assessments are inferred from code and docs, not from rendered output (none were run). Constants as read 2026-10-12.

## 1. SKiDL (`src/skidl/schematics/`: place.py, route.py, decisions.py, backend.py, sch_node.py, snap.py, net_terminal.py)

a) **Placement.** Hierarchical: `Placer.place(node)` places children first, then `group_parts` splits parts into connected groups (shared internal nets) and floating parts. `place_connected_parts`: `add_placement_bboxes` (box padded by one routing channel plus one per connected non-stub pin on that side, scaled by GRID), `add_anchor_pull_pins`, `random_placement`, `evolve_placement` -> `push_and_pull`, `snap_to_grid`. Force-directed: attraction `net_force_dist` (anchor pin to pull pins per net, `pt_to_pt_mult` boosts 2-pin nets), repulsion `overlap_force` (smallest axis move separating overlapping boxes). `total_part_force = scale*(1-alpha)*attract + alpha*repel`, alpha sweeps 0 to 1 (attraction first, then pure de-overlap), up to 1000 iterations per stage. No explicit global cost. Groups >20 parts: `place_connected_parts_rowbased` (BFS from most-connected part, pack in rows, row width 2*sqrt(area)). Floating parts (e.g. bypass caps on stubbed nets): `place_floating_parts`, attracted by `part.similarity()`. `place_blocks` orders blocks by tag 1 (connected) -> 2 (floating) -> 3 (children), attraction 1 / 0.1 / 0.
b) **Orientation.** `adjust_orientations`: 8 orientations (4 rotations x flip), Kernighan-Lin style (greedy best-gain moves, roll back to best prefix, <=10 passes). Cost = `net_tension_dist` (per anchor pin, distance to nearest pull pin) + 75 * `label_overlap_cost` (estimated label flag boxes vs own body, own ref/value text band, neighbours, own other labels; LABEL_REACH 250, LABEL_HALF_H 30, LABEL_BODY_MARGIN 40). Placement repeats if any orientation changed.
c) **Routing.** Own router (route.py), channel style: `create_routing_tracks` extends part bbox edges into tracks, dividing the area into 4-face switchboxes; `Router.global_router` is a face-to-face Dijkstra (`rt_srch`) with face capacities (decremented per net); nets ordered by `rank_net` (HPWL, then pin count, smallest first). Multi-pin nets: start at a random pin face, route to the nearest other, then each remaining pin to the nearest face already on the net (tree growth, not tip-to-tip, but no explicit trunk). Detail: `SwitchBox.route` = greedy left-to-right channel router (`connect_top_btm`, `insert_target_nets`, `connect_splits`, `extend_tracks`, `trim_column_intervals`); on failure flips the box and retries top-to-bottom. Entry `Node.route`.
d) **Power.** place.py has no power logic. decisions.py `find_power_bus_runs`: power pins of 2-pin parts, nets with >=3 such pins, grouped by shared X (column) or Y (row) at 0.1 mm, split at gaps >10 mm, runs of >=3 become a wire bus; segments crossing another part body (0.5 mm inset) are cut; pins inside a run skip their own power symbol. Otherwise `emit_power_symbol(pin, ...)` per pin (backend.py).
e) **Label vs wire.** Explicit `pin.stub`/`net.stub`: stubbed pins/nets get no wire, just a label at the pin (`add_circuit`, `get_internal_nets` skip them). `auto_stub` (`_auto_stub_cross_group`, `_auto_stub_large_groups`) converts nets to labels to shrink groups and cross-group wiring. `net_terminal.py`: NetTerminals when a net spans nodes / single pin / user-named. `decisions.find_overlapping_pins` suppresses duplicate labels at coincident pins; `deconflict_labels` slides a label past a body edge (1.27 mm margin) with a short wire if its projected box hits another body; stub labels never moved.
f) **Spacing.** GRID 50 internal units, snap by first pin; padding by channels per connected pin (density scales with pin count); `expansion_factor`; KiCad grid 1.27 mm.
g) **Quality (frank).** Legible but "organic blob": no signal-flow direction (only tag ordering), no rails/ladders, power not planned as rails except the bus-run rule. Strengths: label-aware orientation, routing that never crosses parts. Weakness: force-directed gives wandering paths; they lean on stubbing nets to avoid hard cases. Nothing hand-drawn-looking in their docs.
h) **Borrow.** Label-overlap term in orientation cost; `find_power_bus_runs`; `rank_net` ordering + capacity decrement for routing order; `auto_stub` to demote long cross-group nets to labels; KL prefix-rollback for orientation passes. **Avoid:** force-directed placement from random starts (non-deterministic, no flow); treating power as an ordinary net.

## 2. circuit-synth (`src/circuit_synth/`)

Schematic file writing is delegated to companion `kicad-sch-api`; the layout layer is a "legacy positioning system" per its ARCHITECTURE docs.

a) **Placement.** `kicad/sch_gen/collision_manager.py` `place_symbol`: snap cursor to grid, padded bbox (+0.5 mm), `CollisionDetector.add_bbox`; on collision shift x by 10 mm, up to 100 attempts, then force-place. Cursor advances by width + 5.08 mm; wrap rows at right margin 25.4 mm with ROW_SPACING 10 mm. `schematic_writer._place_components` uses `place_with_text_flow` (`kicad/schematic/text_flow_placement.py`): left-to-right, wrapping, spacing 15 mm; fallback `_arrange_grid`. `kicad/schematic/placement.py` `PlacementEngine`: AUTO (row scan with collision jump), GRID (10 columns), EDGE_*, CENTER (spiral), force-directed mode whose attraction is defined but never applied. Objective: none (declaration order, no connectivity).
b) **Orientation.** None; unrotated boxes. Power symbol rotation derived from pin angle, +180 for GND.
c) **Routing.** Effectively none in the main path. `kicad/schematic/wire_router.py`: direct / Manhattan L / "smart" (direct, two L's, fallback) per point pair; `route_bus` offsets parallel pairs by 2.54 mm. No multi-pin net handling; `max_segments`, `avoid_diagonal` unused.
d) **Power.** Nets with `is_power` + `power_symbol`: symbol per pin (`_add_pin_level_net_labels`, `_add_power_symbol`, `#PWR01..`), Value text fixed after save by regex (`_fix_power_symbol_text_positions`).
e) **Label vs wire.** Connectivity by labels at pins; `_is_net_hierarchical()` always True, so hierarchical labels everywhere; sub-sheets get sheet pins from shared nets. Writer generates essentially no wires.
f) **Spacing.** Grid 2.54 mm, margin 25.4, component gap 5.08, text-flow 15, row gap 10, multi-unit stack 12.7; fallback symbol sizes 15.24 square (regulators/U), 7.62x5.08 otherwise.
g) **Quality.** A netlist-to-KiCad bridge, not a layout engine; README says "Python for hierarchical structure and repeated blocks, KiCad for custom layout". Output is rows of labelled parts. Its real organisation is one sheet per Python subcircuit.
h) **Borrow.** Little: sheet per block as hierarchy unit; sheet-width estimate from longest net name (`len*1.27 + 10`). **Avoid:** label-only connectivity, declaration-order placement.

## 3. tscircuit (core, `@tscircuit/matchpack`, `schematic-trace-solver`, `bpc-graph`, `autolayout`)

a) **Placement.** Default in `tscircuit/core` `lib/components/primitive-components/Group/`: `Group_doInitialSchematicLayoutMatchPack` -> `applySchematicMatchPackLayoutToTree` -> `@tscircuit/matchpack` `LayoutPipelineSolver` with chips, pins, nets (flags `isGround`, `isPositiveVoltageSource`) and strong direct-connection pairs (`pinStrongConnMap`). Gaps: `chipGap 0.6`, `decouplingCapsGap 0.4`, `partitionGap 1.2` (schematic units). Matchpack internals (partitioning, decoupling-cap grouping, packing) were NOT read, only its interface. Alternatives in the same folder: `...LayoutMatchAdapt` (uses `bpc-graph`: corpus of fixed layouts, `netAdaptBpcGraph`, Weisfeiler-Leman graph distance to pick the best template, `ForceDirectedLayoutSolver`, `singletonKeys ["vcc/2","gnd/2"]`), `...Flex`, `...Grid`, `...Sections` (`computeSchematicSectionLayoutUsingRows`). Older `tscircuit/autolayout`: best of row / column / "central LR bug with ascending columns", then port alignment and a column shift.
b) **Orientation.** Allowed [0,90,180,270]; Chips locked to 0; explicit `schOrientation/schRotation/facingDirection` lock to 0. `getPowerGroundForcedRotation`: a 2-pin part with a pin on a power/ground net is forced so the rail pin is up (power) or down (+180, ground). Rotated footprint used only if it grows size by >= chipGap. bpc-graph `getPinDirection` derives pin side from offset vs box.
c) **Routing.** `schematic-trace-solver` `SchematicTracePipelineSolver`, ~27 stages: `MspConnectionPairSolver` (minimum spanning tree over each direct-connection net: tip-to-tip, our weakness too), `SchematicTraceLinesSolver`, `LongDistancePairSolver`, `UnroutedTraceRecoverySolver`, `TraceOverlapShiftSolver` (nudges parallel overlaps), elbow-simplification solvers, `sameNetJunctionAlignmentSolver`, `traceCleanupSolver2` ("aligning same-net rails"), `railNetLabelCornerPlacementSolver`, `netLabelToTraceSolver`. Chip rectangles are the only obstacles (terminals project to the edge). paddingBuffer 0.1. The long cleanup tail shows the raw routes are untidy.
d) **Power.** Power/ground are nets: not routed, labelled. `availableNetOrientationSolver` picks label orientation; forced part rotation points the rail pin at its label.
e) **Label vs wire.** Policy set at circuit-description level in `Group_doInitialSchematicTraceRender`: `directConnections` -> traces; named `netConnections` -> labels, never routed. `allowInlineNetLabel` names a routed trace inline instead of adding a second label. Ports without a trace get a label (`insertNetLabelsForPortsMissingTrace`); `netLabelToTraceSolver` converts label pairs back to a trace when a clear path exists.
f) **Spacing.** Gaps above; `schMargin*` props; text bounds added to reserved chip size, +0.4 top/bottom for box symbols.
g) **Quality.** Docs mark auto layout as beta. Small circuits (LED+resistor, decoupling caps at a chip) should look tidy thanks to fixed rotations and decoupling grouping; larger ones lean on labels so wiring is sparse. Overlaps from matchpack are only logged, not repaired. Not verified visually. Example: https://docs.tscircuit.com/guides/tscircuit-essentials/automatic-schematic-layout (SVG via svg.tscircuit.com); `autolayout` repo has screenshots in `docs/`.
h) **Borrow.** Forced rail-up/rail-down rotation for 2-pin parts; separate smaller decoupling-cap gap; chip-rectangle obstacle model; post-route cleanup (overlap shift, elbow simplification, same-net rail alignment, inline net label on a trace); WL-hash template matching (bpc-graph) for recurring sub-circuits. **Avoid:** MSP tip-to-tip routing; labels as default for all nets.

## Ranked borrowable ideas

1. **Trunk-and-drop / same-net rail alignment post-pass** (tscircuit `traceCleanupSolver2`, `sameNetJunctionAlignmentSolver`; SKiDL tree growth to nearest existing route): after libavoid, for each multi-pin net choose a trunk on the median coordinate and reroute pins as drops; snap near-collinear same-net segments to a single track.
2. **Power bus runs** (SKiDL `find_power_bus_runs`): in the terminal planner, group power pins of 2-pin parts by shared X/Y, break at gaps >10 mm or body crossings, emit one rail wire with one symbol at its end, drop per-pin symbols for interior pins.
3. **Hard rail-up / ground-down rotation for 2-pin parts** (tscircuit `getPowerGroundForcedRotation`): make it a constraint rather than a prior for support parts; yields vertical rungs between rails in regulator adjust networks.
4. **Sub-circuit template corpus** (bpc-graph WL matching): hash a block's colored adjacency graph, look up a ladder template mined from KiCad demos (relative offsets and rotations); place by template when the distance is small, else fall back to refinement.
5. **Label-overlap cost term and Kernighan-Lin prefix rollback in orientation search** (SKiDL `adjust_orientations`, label weight 75 vs wire tension): add field/label box overlap to the refinement cost and use rollback-to-best-prefix passes to escape greedy local minima (helps main path stop running right-to-left).

None of the three has a signal-flow-direction notion; our ELK layered floorplan is already ahead there.
